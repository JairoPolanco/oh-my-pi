# Changelog

All notable changes to this project will be documented in this file.

## [Unreleased]

### Fixed

- Verification engine fails CLOSED on unknown/malformed check kinds (dogfooding finding): a bare-string check (kind `undefined`) made `#run` fall through and return `undefined`, crashing `verify()` at `r.pass`. The engine now returns a descriptive failing `CheckResult` for any unhandled kind — never `undefined`.

### Added

- Bash write-redirection target scan (`EffectBroker.bashWriteTargetsOutside`): the bash effect resource is the command's CWD, so `echo x > /tmp/f` from the workspace previously authorized — a real fs.write-boundary bypass found by the harness-value benchmark. Now write-redirection targets (`>`, `>>`, `2>`, `&>`) are scanned, `~`/`$HOME`/`$TMPDIR` expanded, and a target escaping the workspace maps to `outside:` (deny). In-workspace redirects, fd merges, and heredocs stay allowed. Pinned by regression test.
- Skill promotion evidence evaluator (`evaluateSkillPromotion`): arms the skill promotion gate with a real decision — paired sandbox-vs-replay trials through the kernel promotion gate PLUS a disjoint held-out split through the sequential design; promotes only when both clear (paste-9's last parked item). Pure + deterministic, no model calls.
- Trusted-verdict ledger path (dead-code fix): new `harness.evaluated` event kind; `KernelHost` registers an operator-scoped `harness.recordEvaluation` gateway method so the metaharness evaluator records promote/reject verdicts into the ledger from another process (the `harness.promote` bridge op then applies the recorded verdict).
- Constitutional kernel package: append-only event bus with DAG parent links and provenance, content-addressed immutable artifact store, capability registry with monotonic child-scope inheritance, policy engine with constraint evaluation, context materializer with scoring and token-budget allocation, verification contracts and deterministic checks, and the AgentRuntime/Actor/DurableTask seam interfaces.
- Kernel actor seam: `actorStatusFromRef` / `kernelActorState` liveness projection, typed `AgentMessage` mailbox envelope codec (`encodeAgentMessage`/`decodeAgentMessage`/`makeAgentMessage`).
- Kernel bridge ops for semantic memory (`memory.propose/commit/recall/stale`), actor liveness (`actors.status/list`), typed messaging (`actors.send`), and capability grants (`capabilities.grant/effective`); `InMemoryMemoryBackend.commit` now matches the `MemoryBackend` interface signature.
- Kernel bridge ops for completion contracts (`contract.create/verify` with deterministic checks against the session cwd), rule-based routing (`routing.register/resolve/record/stats` aggregating per-model usage from the event log), capability policy (`policy.authorize`, default-deny), and security profile (`security.profile` reporting effective capabilities and the derived policy tier).
- Learning plane: falsifiable hypothesis records (`Hypothesis`), parent-linked harness version ledger (`HarnessVersionLedger`, H0 baseline + commit/rollback/ancestry), paired-comparison promotion gate (`evaluatePromotion` with overall non-inferiority + target-slice improvement + cost/latency/reliability/security checks), sequential experimental design (`stageGate`/`runSequentialDesign`: smoke → signal → confirm → full → held-out with early-stop), editable-vs-constitutional component scoping (`isEditable`/`isConstitutional`), and run pairing (`pairTrials`/`summarizePairing`: baseline↔variant trial pairing by task id for the gate).
- Gateway control plane: `Gateway` with typed method registry + operator-scope authorization, channel registration + event fan-out, provider/model/runtime separation, transport attachment (`GatewayTransport`), and a hosted daemon (`startGatewayServer`: HTTP `POST /rpc` JSON-RPC + WebSocket `/ws` event push); kernel bridge ops `harness.hypothesis`/`harness.promote`/`harness.versions` and `gateway.status`.

### Fixed

- Capability scope containment now has real set semantics: `scopeContains` decides Resources(child) ⊆ Resources(parent) on segment structure, closing the `repo/*` ⊉ `repo/**` escalation where a child could widen its authority.
- `ContextMaterializer` enforces ONE global token budget (band weights normalized, caps as soft regularizers); `usedTokens` reports the actual selected tokens, and `ContextView.rendered` carries exactly the content + token count passed to the model (compression no longer discards its own output).
- Task `claim()` is now an atomic transaction: refuses non-ready, blocked, and dependency-incomplete tasks; records the attempt in the same transaction; `reclaimExpired` closes the attempt with `lease_expired`.
- `EventLog` replay is lossless: timestamps (and the full envelope) survive, replay appends with `emit: false`, and the host loads before enabling persistence so restarts never duplicate events on disk.
- `HarnessVersionLedger` separates candidates from the active head: `propose` never mutates active state; only a passed promotion gate (`promote`) advances it.
- Security invariants in the promotion gate are structured `InvariantResult`s — a nonempty string no longer passes as a "passed" check.
- Semantic memory facts have an explicit `state` (proposed/committed/stale/rejected); recall returns committed-only, so `propose` no longer means active.
- `DeterministicVerificationEngine` command checks require an execution gate (wired to the session policy engine); ungated verifiers refuse commands instead of raw `Bun.spawn` — no escape hatch around tool policy.
- Package exports repaired (`./actors`, `./learning`, `./gateway` subpaths; broken `./agents`/`./scheduler` removed).
- Promotion gate now uses paired bootstrap confidence intervals (deterministic seed) instead of mean comparisons: non-inferiority and target-slice checks use the CI lower bound, cost/latency checks the CI upper bound.
- Completion contracts are SQLite-durable (`SqliteContractStore`) — they survive restarts alongside the work graph.
- `HarnessVersionLedger` is SQLite-durable: versions, verdicts and the active head persist across process restarts for regression bisection.
- Gateway daemon `/ws` now performs the actual WebSocket upgrade (`server.upgrade`) — WS clients receive pushed gateway events.
- `KernelHost` composition root moved into the kernel package: every constitutional store (artifacts, tasks, contracts, events, capabilities, memory, policy, models, verification, version ledger, gateway) composes under one roof with one warm/close lifecycle. The coding-agent's bridge is now literally just a bridge.
- Gateway is daemon-scoped: `Gateway.global()` is the ONE control plane above all session hosts. Hosts `attachEvents` their event bus (and detach on close) instead of owning a private gateway instance, so every session's events fan into the same channels and runtime registry.
- `RuleBasedModelRegistry.resolveWith(provider, model, features)` exposes the same policy envelope (effort/turns/verification/delegation calibration) for an explicit provider/model pair — the adapter seam that lets routing through a live registry (OMP's configured model) get identical policy to role-table resolution.
- Context VM is now mathematically truthful (audit): the materializer measures REAL content tokens and either fits a candidate whole or ACTUALLY truncates it (a new, re-measured representation) — never "content unchanged, tokens changed". `objective`/`instructions` are real inputs that become mandatory candidates, and `usedTokens`/`rendered.tokenCount` are measured from the exact rendered content, so `estimateTokens(view.rendered.content) <= spendable` always holds (join separators included).
- Verification identity is passed immutably per call (audit): `StateSnapshot.actor` travels through `verify()` into the command gate — no more mutable `host.evalActor` that concurrent verifications could race. File/pattern/json checks are confined to the workspace root (`../../` escapes are refused), matching the command gate's deny-on-uncertainty.
- Capability containment now agrees with the authorization matcher (audit): `repo/**` no longer "contains" the bare `repo` (the matcher's `^repo/.*$` doesn't match it), and `effective()` returns a principal's DIRECT grants only — the parent chain is an `upperBound()` used for grant validation, implementing least privilege instead of auto-inheriting the parent's whole authority.
- Actor states: `parked` is a first-class state distinct from `blocked` (intentional suspension vs a wait), and `ActorStatus.lastHeartbeat` reflects the real running heartbeat (registry `lastHeartbeat`, bumped on live activity) with `lastActivity` only as a historical fallback.
- `KernelHost` is now the canonical `Kernel` implementation: it implements the formal `Kernel` interface (events, artifacts, tasks, capabilities, policy, memory, models, contracts, verifier, versions, gateway), and the redundant `assembleKernel`/`KernelAssembly` assembly abstraction was deleted — the composition root IS the kernel, there is no separate wiring path to drift out of sync with it (audit #19).
- Added the `skill.promoted` event (`SkillPromoted`) to the harness event model, completing the skill lifecycle (proposed → promoted) the learn pipeline emits.
- Gateway server supports inbound events (audit #14): WS clients stream `{ kind: "event.append", payload }` frames into the daemon's own event log via `GatewayServerOptions.onEvent`, so the control plane accumulates every session's trajectory.
- `ArtifactStore.pathFor(id)` exposes the canonical blob path so aliases (session artifact hardlinks) reference one physical copy instead of duplicating bytes (audit #10).
- EffectBroker — the universal effect boundary (audit #7, blueprint §7/§75): `EffectBroker` maps tool-level effects (file read/write, command execution, network) onto kernel policy operations via `mapToolEffectToOperation` and authorizes them default-deny against the actor's capability set. Exposed on `KernelHost.effects` and the `Kernel` interface. Ungoverned tools pass through with an honest `{ allow: true, op: null }` — never a fabricated denial.
- EffectBroker constitutional mode (paste-4 P0 #3): `denyUnknown: true` denies any tool without an explicit effect classification or pure classification (`PURE_EFFECT` sentinel) — no unknown effectful tool silently passes through. The default mapper now covers the full OMP surface (lsp, inspect_image, ast_grep, debug, eval, github, browser, task, hub, vibe_*, learn, manage_skill, memory_edit, retain, recall, reflect, checkpoint, rewind).
- Capability bootstrap (paste-4 P0 #4): `deriveChildCapabilities` computes C_child = requested ∩ parent-upper-bound and grants exactly that at spawn; `bootstrap` establishes a trusted main-actor baseline (workspace-scoped fs.read/write, process.exec, network) when the effect gate is enabled.
- Gateway server inbound events are authenticated (paste-4 P1): `GatewayServerOptions.authToken` — `event.append` frames without a matching token are dropped, so the daemon event log is not a public write surface.
- Canonical main principal identity (paste-5 P0): `KernelHost` accepts `mainPrincipal` (from the session — OMP's `MAIN_AGENT_ID` is "Main", capital M) instead of hard-coding "main", so the bootstrap and the real actor can't diverge and default-deny the actual main agent under the effect gate.
- EffectBroker resource canonicalization (paste-5 P0): tool arguments are canonicalized against the workspace root before policy — `src/foo.ts`, `/abs/.../src/foo.ts`, and `repo/src/foo.ts` all map to `repo/src/foo.ts`; `npm test` at the repo root maps to `repo/` (covered by `repo/**`); paths/cwds escaping the workspace map to `outside:` and are denied. Filesystem and process authority live in ONE namespace.
- Artifact hashing uses a Bun-native primitive (paste-5 P0): `Bun.CryptoHasher("blake2b256")` with an explicit availability assertion at hash time — the constitutional identity layer no longer depends on `node:crypto` accepting the `blake2b256` alias (standard Node rejects it).
- Verifier commands authorize via the SAME canonical EffectBroker as the bash tool (paste-6 P0 #3): the resource is the canonicalized workspace cwd, not the raw executable name — `bun test` at the repo root is covered by `process.exec:repo/**` instead of being refused against `repo/**` vs `"bun"`.
- Context materializer supports atomic all-or-nothing candidates (paste-6 P0 #4): `CandidateItem.truncatable: false` is included WHOLE or DROPPED — never partially truncated. Tool spans use it so a span is never accounted at 18 tokens while its full ~1000-token content goes to the provider.
- Typed capability ids for governed effects (paste-6 P0/P1): `agent.spawn`/`agent.message`/`agent.kill`, `task.write`/`task.claim`/`task.read`, `memory.write`/`memory.read`, `skill.write`/`skill.read`, `session.state`, `computer.read`/`computer.control` — replacing the fake `process.exec:tool:*` namespaces so the planner's grants and the broker's operations agree on one resource space. `board`/`goal` are no longer classified pure (durable state mutation), and `computer` is mapped.
- Capability grant ceiling is the parent's ACTUAL authority (paste-7 P0 #1): `grant` and `deriveChildCapabilities` are bounded by `effective(parent)` — the parent's own direct grants — NEVER the ancestor chain. A read-only delegated child cannot lean on a grandparent's grant to mint a write capability; `upperBound` remains only for audit/introspection. Grant-elevation escalations are closed at every chain depth.
- Tool effect mapper returns `Operation[]` and compound tools require ALL mapped operations (paste-7 P0 #3): `hub` maps BY OPERATION (start/stop/restart→`process.control`, send-to-agent→`agent.message`, logs/ps/describe→`process.read`, cancel→`job.control`, wait→`job.read`, list/peers→`agent.read`+`job.read`), `task` is `agent.spawn` (TaskTool spawns subagents, not board work), `board` reads are `task.read`, `learn` is `memory.write` (+`skill.write` when a skill payload is present), `goal` has read/write lifecycle ops. One call can require several capabilities — ALL must pass.
- Network authority is the HOSTNAME, not the raw URL (paste-7 P1): `fetch https://example.com/path` maps to `network:example.com` so a `network:example.com` grant cannot be bypassed by path or protocol variations.
- Explicit workspace root for authorization (paste-7 P0 #5): `KernelHost` takes `workspaceRoot` and canonicalizes effect resources against it — the kernel STORAGE dir (session file sidecar) is never the authorization root.
- Effect taxonomy is derived from REAL tool schemas and OMP's own approval declarations (paste-8 P0): `lsp` maps BY ACTION (`LSP_READONLY_ACTIONS` queries → fs.read; rename/rename_file/code_actions+apply → fs.write — a read grant can never rename), `debug` maps BY ACTION (`DEBUG_READONLY_ACTIONS` inspection → process.read; launch/attach/continue/evaluate/breakpoints → process.exec), `security_scan` is process.exec (its tool declares approval "exec" — never fs.read), `computer` classifies on `read_only: true` (the real schema — no `action` field), `manage_skill` create/update/DELETE all require skill.write (delete is a mutation, never skill.read), `checkpoint`/`rewind` share one `session.state:session` resource, and `hub` process ops use the launch `name` as the process identity with peer messaging as the generic `agent.message:actor` (the planner cannot know recipient identities). Main baseline grants name-scoped `process.control:*`/`process.read:*` and `skill.write:promote` alongside the path-scoped grants.
- Durable authority (paste-8 P0): `SqliteCapabilityStore` persists the capability TREE (principals, parent edges, direct grants) under `capabilities.db`; `CapabilityRegistry` write-throughs every mutation and `KernelHost.warm()` restores the snapshot — a cold-revived actor rejoins the SAME constrained tree (park → restart → revive → same authority), never zero and never re-bootstrapped as root.
- Hub stdin sends are exec-tier process control (paste-9): `hub {op:"send", name:"..."}` maps to `process.control` with effect `execute` — matching the baseline/planner grant surface (`write` never matched and denied every stdin send).
- Harness ledger capabilities (paste-9): `harness.propose` (write), `harness.promote` (execute), and `harness.read` are bootstrapped for the main principal — the RLM bridge gates `harness.hypothesis`/`harness.promote`/`harness.versions` against them.
